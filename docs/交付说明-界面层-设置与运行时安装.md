## 2. 每个界面能做什么

### 设置页（`CASettingsViewController`）
- **Provider**：`base_url`、`api_key`（`secureTextEntry`，保存后显示「已保存，重新输入以覆盖」）、`model`、上下文窗口、推理强度；「保存 Provider 配置」把值写进 `NSUserDefaults`（`CodexAPIBaseURL` / `CodexSelectedModel` / `CodexThirdPartyModel` 等）并调 `CAProviderConfiguration -saveAPIKey:error:` 落盘 0600；「测试连接」GET `<base>/models` 报 HTTP 状态；「清除密钥与配置」删密钥文件 + `removeLegacyKeychainCredential` + 清 defaults。
- **模型**：显示当前模型；「选择模型」列出 `CAModelPricingManager.prices` + 已保存候选（前 20 个 + 手动输入），选中即写 defaults 并调 `CAThirdPartyModelCatalog +modelInfoForSlug:…` / `+writeCatalogForModels:selectedModel:contextWindow:error:` 写 codex `model_catalog_json`；「推理强度」用 `+reasoningLevels`；「模型价格目录」显示 `modelCount` 并可 `refreshCatalogWithCompletion:` 刷新。
- **Codex Runtime**：显示「已安装版本 / 未安装」与「可更新：旧 → 新 / 已是最新」；「检查更新」刷新 `CARuntimeCatalog`；「下载安装 / 修复」弹出更新页；「运行时管理」列出清单条目（含已安装标记、大小、安装根）；「刷新运行时清单」「清理运行时下载缓存」。
- **MCP 桥**：开关启停 `CAMCPBridge`（`startOnPort:CAInternalMCPPort error:` / `stop`），并把 `[mcp_servers.codexapp] enabled = true/false`（首次会补 `url = "http://127.0.0.1:27018/mcp"`）经 `CAComposerCatalog -setMCPServer:enabled:completion:` 写回 `config.toml`；状态行与 config.toml 查看/复制。
- **环境**：`CAExecutionEnvironment` 探测结果（环境类型 / 越狱证据 / TrollStore / root 模式 / 家族品牌 / 启动器 / shell / 证据）、关键路径（support、codexHome、config.toml、密钥文件、运行时目录、日志、下载缓存、tmp）、Python / Theos 运行时的安装状态与一键安装。
- 入口：日志查看（`CALogViewerViewController`）、诊断（`CADiagnosticsViewController`）。

### 诊断页（`CADiagnosticsViewController`）
- 原「概览/网络/远端开关/运行时/环境/shell 探针/MCP 桥/登录态」保留；新增「安装」分区：
  - **一键安装 / 修复必需运行时**：按清单找出缺失的必需运行时，串行安装（0.5s 刷新进度）；
  - **安装状态 / 当前阶段**：如 `codex · 下载 · 下载中（45%）`，行内 `UIProgressView`；
  - **失败项**：每个失败运行时的原因；失败弹窗里直接附最近日志并给「查看完整日志」；
  - **最近日志**：`CALogger -currentLogText` 尾部；点击进日志查看器；
  - **签名模板**：显示实际用于 codex-sign 的 entitlements 路径（缺失时明确提示）；
  - 每个必需运行时一行，点击进入带阶段进度的安装页。
- 更多菜单新增「一键安装/修复运行时」。

### 更新页（`CAUpdateViewController`）
- 展示 5 个阶段（下载 / 校验 / 解包 / 签名 / 安装）的进行状态与总进度、字节数、阶段文案；
- 失败时显示原因 + 「重试」，并可「查看日志」跳到 `CALogViewerViewController`；
- 支持 `-initWithVersion:`（codex）与 `-initWithPythonVersion:` / `-initWithReverseToolsVersion:` / `-initWithTheosVersion:`，以及 `-initWithRuntimeID:version:`。

### 外壳（`CARootViewController`）
- 顶部标题 + 会话 / 设置 / 诊断三入口的全功能容器；`+launcherRootViewController` 直接把会话页作为内容区。

## 3. 调用的核心 API（不重新实现）

- 路径/目录：`CARuntimePaths`（`runtimeRootForID:`、`installedManifestPathForRuntimeID:`、`archiveCachePathForEntry:sha256:`、`ensureDirectory:mode:error:`、`writeFileAtomically:contents:mode:error:`、`configTOMLPath` …）
- Provider：`CAProviderConfiguration`（`readAPIKeyWithError:`、`saveAPIKey:error:`、`removeLegacyKeychainCredential`、`normalizedBaseURL:`、`modelsURLForBaseURL:`）
- 清单：`CARuntimeCatalog`（`sharedCatalog`、`entryForID:`、`entries`、`refreshNowWithCompletion:`、`CARuntimeCatalogDidChangeNotification`）+ `CARuntimeCatalogEntry`
- 下载/校验/签名：`CAUpdateManager`（`cachedPackageAtPath:matchesSHA256:`、`fetchOfficialSHA256ForAsset:version:completion:`、`signPaths:staging:error:`、`findExtractedBinariesIn:codexPath:hostPath:`、`pruneRuntimeDownloadCacheExceptVersion:`）、`CAArchiveExtractor`（`extractTarGzip:…` / `extractRuntimeFromDeb:…`）
- 引擎/目录：`CACodexEngine`（密钥、`resolveCodexExecutable`、登录四路）、`CAThirdPartyModelCatalog`、`CAModelPricingManager`
- MCP：`CAMCPBridge`（`startOnPort:error:` / `stop` / `running` / `reportedInternalMCPTransportFailure`）+ `CAComposerCatalog`（config.toml 改写）
- 其它：`CAExecutionEnvironment`、`CAStorageManager`、`CALogger`、`CALogViewerViewController`、`CACommon.h` 的 `CAInternalMCP*` / `CADownloadProxyPrefixes()`

## 5. 未完成 / 需要注意（具体）

1. **`CAAppDelegate` 未改**：启动路径仍是「`CAChatViewController` 作根 + 右上角设置按钮」，`mtagent://settings|logs|diagnostics` 原样可用。`CARootViewController` 已实现但没有接进 `CAAppDelegate`（避免与并行改动冲突）；若要三入口常驻，只需把 `didFinishLaunchingWithOptions` 的根换成 `[CARootViewController launcherRootViewController]`。
2. **签名模板不在 bundle 清单里**：`build/bundle_manifest.json` 没有 `ResignEntitlements/*.plist`，而 `CAUpdateManager -signPaths:staging:error:` 固定使用 `<bundle>/ResignEntitlements/helper.entitlements.plist`。界面层做了两件事兜底：更新页在签名前若发现该文件缺失，会尝试从 bundle 内其它 entitlements 模板（`runtime.entitlements.plist` / `entitlements.plist`）补齐；诊断页「签名模板」行会明确显示实际路径或缺失。**根因修复需要改 `build/`（本轮不允许）**：把 `MTAgent/ResignEntitlements/{runtime,helper}.entitlements.plist` 加进 manifest + 装配脚本。
3. **没有真机/真 SDK 编译**：本机是 Windows，只能做静态检查（见上）。iOS SDK 编译与 `make -C build` 需在 macOS CI 上再跑一次确认。
4. **空壳未全量实现**：只实现了界面真正用到的方法；`CASettingsViewController` 仍有 41 个、`CADiagnosticsViewController` 的其它占位选择器仍未实现（保持 `return nil`），未删除任何声明。
5. **`CASettingsViewController.h` 中 9 个占位声明按 `SPEC/method_types.json` 校正了返回类型**（`applyThirdPartyModelSelection:`→`bool`、`clearThirdPartyConfiguration`/`handleSelectReasoningEffort`/`presentThirdPartyModelPicker:`/`showInstalledCLIVersion`/`showPythonEnvironment`/`showTheosEnvironment`/`testThirdPartyConnection`→`void`、`formattedByteCount:`→`id` 且参数 `unsigned long long`），因为实现是按真实行为写的；选择器名一个没删，覆盖度未变。
6. **MCP 内部服务名取 `codexapp`**（`CAComposerCatalog +isInternalMCPName:` 认可的名字），config.toml 段为 `[mcp_servers.codexapp]`；若原包实际用别的名字，改 `kSettingsInternalMCPName` 一处即可。
7. **`kickAutomaticRuntimeRecovery` 不自动下载**：打开诊断页只探针+日志（避免未确认就拉几百 MB），真正的下载仍由「一键安装/修复」触发。
8. Python / Theos / 逆向工具运行时的安装入口已通（设置页环境分区、运行时管理、`initWithPythonVersion:` 等），但能否装成功取决于远端 `runtime-manifest.json` 是否包含对应条目。
